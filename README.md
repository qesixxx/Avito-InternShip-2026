## Avito QA Internship Auto-tests Project

### Обзор проекта

Репозиторий содержит комплект автоматизированных тестов и тестовую документацию для API сервиса объявлений (Avito Internship API (2026))

### Эндпоинты API

В рамках проекта протестированы следующие методы сервиса:
```
POST /api/1/item #создание нового объявления.
GET /api/1/item/{id} #получение подробной информации по ID.
GET /api/1/{sellerID}/item #получение всех объявлений                                     # конкретного продавца.
GET /api/1/statistic/{id} #получение счетчиков статистики                                #(лайки, просмотры, контакты).
DELETE /api/2/item/{id} #удаление объявления (версия API v2).
```
### Основные задачи проекта

* Проверка бизнес-логики создания и получения объявлений
* Выявление критических уязвимостей
* Анализ стабильности и обработки граничных значений
### 📂 Структура проекта

- `tests/` - директория с автоматизированными тестами на Python (Pytest)
- `TESTCASES.md` - файл с подробным описанием тест-кейсов (позитивные/негативные сценарии, корнер-кейсы, функциональные/нефункциональные проверки)
- `BUGS.md` - реестр найденных дефектов с приоритетами и шагами воспроизведения
- `requirements.txt` - список зависимостей проекта.
### 🛠 Стек технологий

- **Язык программирования**: Python 3.12.3
- **Тестовый фреймворк** - Pytest 
- **HTTP-клиент**: Requests - для взаимодействия с API (REST)
- **Инструмент отладки:** Postman - использовался для предварительного исследования API, проектирования запросов и поиска багов вручную.
- **Плагины:** `pytest-rerunfailures` - для автоматического перезапуска тестов при нестабильности сетевого соединения (ошибки 504/502).

### Инструкция по запуску

1. Подготовка виртуального окружения. Введите в терминал
 ```
 python -m venv venv                                        
 venv\Scripts\activate #для Windows                            
 source venv/bin/activate #для macOS/Linux 
 ```

2. Установка зависимостей
 ```
  pip install -r requirements.txt  
 ```   
  
3. Так как тестовый стенд периодически возвращает ошибки **504 Gateway Timeout**, тесты настроены на автоматический перезапуск:
```
pytest -v -rxXs --reruns 3 --reruns-delay 1    
```

`-v` : подробный вывод названий тестов.
`-rxXs`: отчет по пропущенным, упавшим и ожидаемо упавшим (xfail) тестам.
`--reruns 3` : автоматический перезапуск при сетевых лагах.

### Особенности

В проекте используются маркеры `@pytest.mark.xfail` для тестов, которые проверяют **известные баги** (например, XSS в поле `name` или `0` в статистике). В итоговом отчете они будут помечены как `XFAIL`, что является ожидаемым поведением и подтверждает наличие задокументированных дефектов.

### Ограничения 

- Тестирование проводится на нестабильном QA-стенде  
- Возможны флаки из-за сетевых ошибок (502/504)  
- Отсутствует строгая спецификация API, поэтому часть ожидаемых результатов основана на фактическом поведении сервиса
